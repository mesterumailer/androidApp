# SMS Manager for Android

مدیریت و تحلیل پیامک‌های دریافتی روی Android، با تمرکز اولیه روی **فاز ۱: خواندن Inbox و استخراج اطلاعات مهم**.

> وضعیت فعلی: نسخه `0.1.0` — MVP اولیه

## هدف پروژه

این پروژه قرار نیست در نسخه‌های اولیه جایگزین برنامه پیام‌رسان پیش‌فرض Android شود. هدف فاز اول این است که بدون تبدیل شدن به Default SMS App:

- پیامک‌های دریافتی موجود در Inbox را بخوانیم.
- پیامک‌ها را در یک رابط کاربری ساده نمایش دهیم.
- پیامک‌ها را بر اساس قواعد اولیه دسته‌بندی کنیم.
- اطلاعات مهم مثل OTP و مبلغ تراکنش را استخراج کنیم.
- معماری را طوری جلو ببریم که در فازهای بعدی قابلیت‌های تحلیل پیشرفته‌تر به آن اضافه شود.

## فاز ۱ — پیاده‌سازی فعلی

### قابلیت‌های موجود

- درخواست runtime permission برای `READ_SMS`.
- خواندن پیامک‌های Inbox از `Telephony.Sms.Inbox`.
- نمایش حداکثر ۲۰۰ پیام اخیر.
- نمایش فرستنده، زمان، متن و دسته‌بندی.
- دسته‌بندی اولیه:
  - کد تأیید (OTP)
  - تراکنش مالی
  - ارسال و تحویل
  - خدمات
  - تبلیغاتی
  - سایر
- استخراج اولیه کدهای ۴ تا ۸ رقمی برای پیام‌های OTP.
- استخراج اولیه مبلغ تراکنش در قالب‌های رایج متنی.
- تست واحد برای classifier.

### عمداً خارج از فاز ۱

- Default SMS App شدن
- ارسال SMS
- حذف SMS
- تغییر یا دستکاری SMSهای موجود
- دریافت زنده SMS از طریق BroadcastReceiver
- همگام‌سازی ابری
- حساب کاربری
- مدل‌های ML/LLM برای طبقه‌بندی
- ذخیره‌سازی دائمی اختصاصی پیامک‌ها در دیتابیس

## نیازمندی‌ها

- Android Studio با Android SDK مناسب پروژه
- JDK 17
- Android API 35 برای compile/target
- حداقل Android API 26

## اجرای پروژه

۱. این repository را clone کنید.

۲. پروژه را در Android Studio باز کنید و اجازه دهید Gradle sync شود.

۳. برنامه را روی یک دستگاه یا emulator اجرا کنید.

۴. در اولین اجرا، مجوز خواندن SMS را تأیید کنید.

۵. با دکمه «به‌روزرسانی» Inbox را دوباره بخوانید.

> برای تست واقعی Inbox بهتر است از یک دستگاه Android دارای پیامک یا emulator با داده‌های SMS تستی استفاده شود.

## امنیت و حریم خصوصی

- در فاز فعلی فقط `READ_SMS` درخواست می‌شود.
- متن پیامک در log چاپ نمی‌شود.
- پیامک‌ها در این نسخه در دیتابیس جداگانه ذخیره نمی‌شوند و هنگام refresh مستقیماً از SMS Provider خوانده می‌شوند.
- هر قابلیت جدیدی که به SMS دسترسی داشته باشد باید حداقل دسترسی لازم را درخواست کند.

## مسیر توسعه پیشنهادی

### Phase 1.1 — بهبود Inbox

- جستجو در پیامک‌ها
- فیلتر بر اساس دسته‌بندی
- مرتب‌سازی
- نمایش فقط پیامک‌های مهم
- استخراج دقیق‌تر OTP و مبلغ
- پشتیبانی بهتر از فارسی/انگلیسی و اعداد فارسی

### Phase 1.2 — دریافت پیامک جدید

- افزودن `RECEIVE_SMS`
- دریافت پیامک جدید با `BroadcastReceiver`
- به‌روزرسانی UI بدون refresh دستی
- جلوگیری از پردازش تکراری

### Phase 1.3 — ذخیره‌سازی و پردازش

- اضافه کردن لایه persistence در صورت نیاز
- نگهداری نتیجه تحلیل
- تعریف مدل داده پایدار برای classification

### Phase 2 — تحلیل هوشمند

- استخراج entityهای بیشتر
- تشخیص فرستنده/سرویس
- تشخیص نوع تراکنش
- امتیازدهی اهمیت پیام
- معماری قابل اتصال به classifier هوشمند

### Phase 3 — اتوماسیون

- قوانین قابل تنظیم توسط کاربر
- workflow برای پیامک‌های خاص
- در نظر گرفتن قابلیت‌های پیشرفته Android بدون ورود زودهنگام به نقش Default SMS App
